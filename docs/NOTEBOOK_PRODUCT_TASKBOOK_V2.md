# Notebook 产品迭代任务书 V2

## 0. 文档定位与执行约定

日期：2026-10-20。本文依据用户本次明确需求、原《Notebook VNext 迭代方案》和当前工作区源码重写。用途：直接交给开发 agent 实施及产品验收。

本轮产品目标：**用户可以分析一篇笔记或知识库文档，获得可追溯的总结和可操作的思维导图；也可以独立使用以笔记为节点的知识图谱，浏览笔记之间的链接、反向链接和局部关系。**

优先级：本文的产品范围与验收定义优先于原任务书中“跨文档概念图谱为主线”的设定。原任务书关于来源真实性、权限、版本和回归的安全要求继续保留。旧文档的执行指令是历史内容，不是本次要求重新执行 N0 的授权。

本次交付为需求与设计文档，不是功能实现。现有生产代码和未提交改动均须保留；开发开始时重新确认 SHA、diff、迁移链和运行环境。不能只按 Git HEAD 恢复，因为本次检查的主要新功能在未提交工作区。

交付完成标准是本文的用户操作可以在真实页面完成，包含可发现的入口、有效数据、交互和失败恢复。新增页面文件、API 返回 200、lint/build 通过，均不能单独作为产品交付完成的证据。

## 1. 先纠正三个产品概念

| 能力 | 分析对象/节点 | 关系含义 | 主要用途 | 是否依赖 AI |
|---|---|---|---|---|
| 文档分析 | 单篇笔记或知识库文档 | 总结结论与原文证据的关联 | 理解一篇内容，查看概要、章节、要点、概念与来源 | 生成分析需要；读取已生成结果不需要重新调用 |
| 思维导图 | 当前来源的主题、章节、要点 | 层级父子关系 | 结构化理解当前内容 | 可复用已核验分析产物，不需额外模型调用 |
| 笔记知识图谱 | 一篇笔记一个主节点 | 笔记之间的显式内部链接、手动关联 | 在自己的笔记网络中探索、阅读和建立关联 | **基础图谱不依赖 AI、embedding 或文档分析任务** |
| AI 概念关系图（保留扩展） | 从多份来源抽取的概念/实体 | is_a、depends_on 等概念语义关系 | 进一步的研究分析 | 依赖 AI；不是本轮笔记图谱的替代品 |

关键原则：**思维导图 ≠ 笔记知识图谱 ≠ AI 概念关系图。** 开发和验收必须按独立能力描述，不把现有概念图换个标题便交付为笔记图谱。

### 1.1 已确认需求与本任务书采用的默认决策

- 用户已确认：图谱主要面向笔记；分析对象可以是笔记，也可以是知识库文档；需要类似 Obsidian 的知识图谱体验；需要完善功能入口和前端设计。
- 本任务书据此确定首版：图谱默认只显示当前用户有权读取的笔记；显式链接和手动关联为真实边；全局图与局部图均为必做；分析工作台有独立主导航入口。
- 默认不把 PDF、AI 概念和标签全部混成主节点。标签先作为筛选/颜色分组；知识库文档先作为笔记的来源附件或分析对象。
- 本轮采用现有 Note 的个人归属。当前 `Note` 没有 `space_id`，不得为复用文档图谱的空间筛选而假造笔记空间。将来笔记空间化需独立定义权限与迁移。
- 沿用现有 Vue、Markdown 编辑器、登录、主题和布局框架，改进工作流与局部页面，不重新设计登录、组织管理和整个站点。
- 完整 Obsidian 文件系统、插件生态、块嵌入语法、多人实时协同、全自动实体知识库不属于首版承诺。

## 3. 信息架构与明确入口（首批必做）

### 3.1 主导航

桌面 Sidebar 顺序采用：**笔记 / 文档分析 / 知识图谱 / 知识库 / AI 对话 / 每日回顾**。保留个人、设置、组织等现有次级入口。分析和图谱在任何主页面都能一键到达，禁止只藏在知识库按钮或悬浮 tooltip。

移动端底部导航保持最多 5 项：**笔记 / 分析 / 图谱 / 知识库 / 更多**；更多含 AI 对话、回顾、个人与设置，不能让旧功能消失。折叠侧栏仍需 title、可访问名称与当前项高亮。

### 3.2 路由与按钮契约

下列新路由为目标设计，不表示现已存在。旧路由保留兼容跳转；未保存笔记不能被重定向丢失。

| 位置 | 可见文案与行为 | 目标 |
|---|---|---|
| 主导航“文档分析” | 打开来源选择 + 分析历史，不自动付费生成 | `/analysis`（拟新增） |
| 知识库每一行 | 清晰的文字操作“分析”，更多菜单也可保留同操作 | `/knowledge/:id/insight` 可继续复用 |
| 笔记编辑页工具栏 | “分析笔记”，旁边或更多菜单提供“局部图谱” | `/notes/:id/insight`、`/graph?focus=:id&depth=1` |
| 笔记列表工具栏 | “知识图谱”文字按钮 | `/graph` |
| 主导航“知识图谱” | 默认打开笔记全局图，不要求先生成摘要 | `/graph` 重做为笔记图谱 |
| 图谱详情“打开笔记” | 进入实际笔记；返回图谱保留筛选/视野 | `/notes/:id` |
| 分析结果“保存为笔记” | 先预览、再由用户确认新建，并保留来源 | 创建一篇新 Note，不覆盖原笔记 |

现有概念图页面可保留为实验性“AI 概念图”，例如 `/graph/concepts`；不占据默认图谱，不删除既有概念或重新解释旧概念 ID。

### 3.3 分析首页

`/analysis` 主区域上方是“选择要分析的内容”，分“笔记”“知识库文档”两类，可搜索标题/文件名，并显示资源类型和更新时间。下方为最近分析结果列表，列包含名称、类型、结果状态、时间和“打开/生成/重试”。无历史时展示两张明确入口卡，而不是一页空白统计。

不强制用户重新上传已有文档。可提供“上传新文档”，复用现有上传流程，上传成功后选择资源；不能创建第二套文件保存、权限或索引系统。

## 4. 文档分析：单篇来源的阅读与理解工作台

### 4.1 桌面布局

以 1440×900 为参考设计画板，使用应用主区域全宽、全高；不要在大屏中间留下一个 1080px 的卡片岛。原 AppShell 继续承载站点导航，页面内部只设置一条紧凑工具栏。

```text
主导航 │ 面包屑 / 来源标题 / 笔记或文档   任务状态   重新分析 · 保存为笔记 · 导出
       ├──────────────────────────────┬────────────────────────────────┤
       │ 原文（目录可收起）           │  总结  |  思维导图              │
       │ PDF 页 / Markdown / 规范文本 │  概览、要点、章节、概念         │
       │ 点击结论后定位并高亮         │  或可平移缩放的导图画布         │
       │ 原文有自己的滚动位置         │  分析区独立滚动/独立画布         │
       └──────────────────────────────┴────────────────────────────────┘
```

默认原文 44%、分析 56%，允许拖动分隔条；目录按需展开，不能永久占满三四个侧栏。窄屏变为“原文 / 总结 / 导图”分栏切换；证据使用局部定位或底部面板，不在桌面每次点击都用全屏遮罩遮住阅读内容。

### 4.2 分析产物

两类来源共用分析能力，不共用错误身份：

- 笔记读取当前已保存正文和标题；进入分析前若有未保存修改，必须等待保存成功或明确选择分析已保存版本。当前 handleSave 吞错误后仍导航的路径要修正。
- 知识库文档读取有权限的原文件/已验证提取文本；文本可解析时不应因 embedding 故障禁止分析。当前仅 indexed 时显示入口的前端条件需按实际文本可用能力调整，不能让前后端契约相反。
- 首版必须支持笔记、Markdown、TXT、文本型 PDF、DOCX；PPTX 复用现有真实幻灯片提取并单独测试。扫描 PDF 缺文本层需明确提示“需要 OCR/暂不支持”，不把空输出当成功。
- 结果包括概览、关键要点、章节摘要、关键概念、待思考问题。事实性要点与章节 claim 关联具体锚点；问题、建议、推测标清类型，不包装成原文事实。
- 长内容按章节/有界片段逐段分析，再聚合。需要有来源覆盖统计与预算边界；预算不足时显示“部分内容已分析”和缺失章节，禁止将抽样结果标为全文总结。
- 结果的“查看来源”始终可用；结果导出为 Markdown，包含可读来源标题、位置和系统内来源链接，不暴露物理路径/密钥。

### 4.3 点击结论与原文定位

点击证据标识后：原文面板滚动到对应页/章节/片段并高亮；多来源要点可切换支持片段，不能只打开第一条。PDF 用受保护的文档 ID 预览接口读取，不能把宿主文件路径暴露为 URL。

优先 PDF 页内文本或页码定位；DOCX/PPTX 可显示规范化提取文本、章节/幻灯片号。格式无法精准渲染时显示“定位到提取文本/原文片段”，并提供有权限的原文件下载。只有实际页码可用时显示页码，不能为了 UI 好看构造页号。

原文高亮以服务端核验版本/偏移为准；锚点过期、文档删除或无权限时显示明确状态并停止加载，不保留旧引用正文。引文匹配只能证明文字确实存在，UI 不应以“可核验”暗示结论绝对正确。

### 4.4 任务、刷新与重生成

业务状态至少区分：未生成、排队、分析中、部分结果、可用、失败、过期、来源不可用；进度按真实阶段显示“解析/分段分析/汇总/生成导图”，没有测量依据不显示伪百分比。

- 默认手动生成；上传后可提供“完成后自动分析”显式选项，默认关闭，防止隐式模型成本。
- 重复点击复用在途 job；刷新、切换页面、重新登录后从服务端恢复当前任务状态，不只依赖当前页面的 setTimeout。
- 路由从 A 切到 B、账号切换或退出时，旧轮询/证据请求的迟到结果不得写进新页面；监听资源身份变化并取消/忽略旧请求。
- 来源更新后提示“结果对应旧版本”；不把旧证据用于新正文。保留用户可读的历史结果需单独标历史且重新授权，不继续假装当前有效。
- 重生成失败时保留此前仍有效的结果；用户编辑与 AI 新结果保存为独立 revision/编辑层，不能强制覆盖。源版本、生成尝试、已发布产物修订版本分别建模。
- 生成失败要有原因和重试入口；provider、队列、权限、解析错误分类展示，不统一成“没有内容”。

## 5. 思维导图：必须是一张可操作的层级图

主视图是根主题 → 主题/章节 → 要点的图形画布；可以从左到右或中心向两侧布局。现有纵向树保留为“大纲模式”和无障碍替代，名称不能继续冒充已完成的画布。

### 5.1 必做交互

1. 拖动空白平移；滚轮/触控板缩放；工具栏提供放大、缩小、适应画布、重置视图和全屏。
2. 点击分支展开/折叠；默认只展开适量层级，保留选中分支，不能把 100 个节点一次堆成文字墙。
3. 搜索节点并定位，高亮命中路径；缩放时节点标题有换行和最小可读尺寸。
4. 单击选中显示节点内容及来源；双击或编辑动作修改标题，支持调整同级顺序。用户修改明确标识，保存后刷新仍在。
5. 重新生成先展示“保留用户修改/生成新版本”，默认保留旧修订；不能悄悄清除标题和顺序。
6. 导出 SVG、PNG 和 Markdown 大纲；导出当前可见图或完整图需选项明确，深色主题导出需保证文字/背景对比。
7. 没有证据的纯组织节点可以存在，但需标为结构节点；事实性节点必须可查看来源。支持键盘选中和层级列表，不强制鼠标才能读信息。

结构必须校验循环、孤立子节点、重复 ID、最大节点/深度，过长文本不直接塞进小节点。默认生成目标 30–80 节点；100 节点作为首版交互验收样本，超限采用折叠或明确截断提示。

实现选择：在当前 Vue 技术栈上优先评估 Vue Flow + Dagre/ELK 的层级布局；最终选型记录原因、许可证、锁定版本和包体积。不是只安装库就完成，也不必为了同时复用网络图强迫两种图共用一个布局引擎。

## 6. 笔记知识图谱：按 Obsidian 类体验重新定义

### 6.1 节点与边的固定规则

- 一个笔记 ID 对应一个主节点；节点展示笔记标题、类别/标签与连接数。笔记改标题不改变节点身份，不按标题合并同名笔记。
- `explicit_link`：笔记正文中的显式内部链接 A→B；保存后自动建立/更新。反向链接是同一关系的反向查询，不创建一条 B→A 伪正文链接。
- `manual_relation`：用户在图谱或关联面板明确建立的关联，带操作者、可选说明；显示为“手动关联”，不伪装成源文引用。用户可以添加/移除，删除它不修改正文显式链接。
- 同一 A/B 多次正文引用显示一条聚合连线，保留引用出现次数和每处位置。A→B 与 B→A 可以在详情区别；默认线条不满屏箭头，悬停/选中时强调方向。
- 同标签不等于显式链接；可用颜色/筛选体现，不自动创建全连接网络。语义相似也不自动充当真实关系。
- 无链接笔记是合法孤立节点，默认可见并可切换隐藏；不需要先分析、先建立概念或购买模型调用才能出现。
- AI 推荐关系为后续增强项：虚线、默认关闭、说明推荐依据，确认后成为手动关联；拒绝后同一来源版本不反复推荐。不纳入首版基础图谱完成的前置条件。

### 6.2 编辑器内部链接与反向链接（首版必做）

输入 `[[` 出现当前用户有权限的笔记搜索候选，显示同名区分信息；选中后绑定稳定 note_id，展示标题/别名。建议持久可解析语法为 `[[note:<uuid>|显示文字]]`，并支持用户键入 `[[标题]]`、`[[标题|别名]]` 后解析；这属于本产品适配，不宣称完全兼容 Obsidian 的磁盘文件语义。

解析规则必须确定：

1. 只解析 Markdown 正文的有效链接节点；代码围栏、行内代码、转义文本中的 `[[...]]` 不建立边。
2. `[[标题]]` 在当前可读范围唯一匹配时绑定；重名显示待选择/未解析，不任取第一条。不向用户提示无权限的同名笔记存在。
3. 系统插入链接使用稳定 ID；历史标题链接解析后保存 occurrence 的目标 ID，改名不能静默指向另一同名笔记。改名后可以保留原显示文字作为别名；自动修改正文需要显式策略与版本冲突保护。
4. 删除链接后更新对应 occurrence；同一 A→B 仍有其他 occurrence 时连线仍在，全部删除才移除 explicit_link。
5. 未解析链接单独列出；默认不画成真实笔记。可由用户主动“创建笔记/选择已有笔记”，不能输入一个标题就自动批量建空笔记。
6. 编辑器侧栏至少有“链接到 / 被链接 / 手动关联”三类，正文链接和反链展示所在段落并能定位。当前“相关笔记”推荐保留但单独命名，不能当反链计数。
7. 新建笔记保存成功后立即能进入图谱/分析；保存失败停留编辑器并保留草稿。现有保存错误后仍去分析的行为要纳入回归。

### 6.3 全局图与局部图

全局图默认展示本人可读笔记网络。局部图聚焦当前笔记，可切换 1/2 跳，区分出链/入链/手动关联；面板中显示当前深度及返回全局按钮。

网络采用能反映连接结构的力导向布局，布局稳定后停止抖动；不是把全部节点放在圆周上。新增/筛选保留已存在节点位置，拖动节点可临时固定并能解锁；返回图谱恢复视野和选中节点。

必做操作：平移、缩放、拖节点、适应视图、搜索定位、悬停高亮邻居、单击预览、双击/明确按钮打开笔记。拖动不能误触打开；触屏用单击预览再点打开。

筛选至少包含：标题搜索、标签、分类、孤立节点、关系类型；按标签或分类分组着色。节点大小可反映当前有权限范围的连接度，并设置上限；不能用 AI 证据条数替代笔记连接数。

### 6.4 图谱布局和详情面板

```text
主导航 │ 知识图谱     全局 / 当前笔记局部图       搜索笔记          筛选
       ├────────────────────────────────────┬───────────────────┤
       │                                    │ 当前选中笔记      │
       │           可交互网络画布           │ 标题、标签、摘要  │
       │     笔记节点 + 真实链接/手动连线    │ 打开笔记 / 分析   │
       │                                    │ 出链 / 入链       │
       │  左下角：可见节点/边、截断提示      │ 局部图 / 关联操作 │
       │  右下角：缩放、适应、布局暂停      │ 连线来源段落      │
       └────────────────────────────────────┴───────────────────┘
```

画布是视觉主体，详情栏默认 300–340px、可关闭。筛选使用小面板按需展开，不常驻占掉半个画布。未选中时详情区显示简短操作提示，不堆多层空卡片。

只有一篇笔记时显示孤立节点和“在正文输入 [[ 创建链接”的引导；没有笔记时“新建笔记”；有笔记无边时展示节点并提供关联引导；服务错误展示重试。**禁止再提示“先去文档洞察生成摘要才有图谱”。**

### 6.5 数据与一致性要求

拟新增逻辑实体（名称可按仓库规范调整）：

- `NoteLinkOccurrence`：owner、source_note_id、source_revision、target_note_id 可空、原始 token、显示文字、正文位置、解析状态；多个 occurrence 汇聚成一条正文关系。
- `NoteManualRelation`：owner、端点稳定 ID、可选说明、created_by、创建/更新时间；端点对与关系类型有去重规则。
- Note 内容版本：若现有 updated_at 不足以做条件保存，引入最小 revision/内容 hash，避免旧任务删除新链接或旧草稿覆盖新正文。
- `NoteGraphViewState` 可先存本地按用户划分的筛选/视野；不能混入账号凭据。需要跨设备再单独服务端持久化。

不建立另一份笔记正文真相表。链接解析应基于提交成功的正文版本、幂等替换本版本 occurrence；旧异步解析发布时复核版本。显式链接持久化/删除与 Note 生命周期使用清晰事务边界，AI/向量索引故障不阻断正常笔记链接图谱。

笔记删除后该节点、连接、反链和搜索结果不可见，正文中的旧链接显示目标失效，不自动重绑同名新笔记；恢复能力按现有删除产品契约执行，不在本轮偷偷引入回收站。

图 API 的节点、边、计数、详情、候选搜索和来源段落均复核权限；隐藏端点不返回边、标题、度数或摘要。候选请求、局部展开、批量详情有上限，禁止逐节点 SQL 和一次性全库正文读取。

## 7. 前端设计规范：以实际页面验收

### 7.1 视觉方向

定位为安静、清晰、以内容为主的知识工具。借鉴 Obsidian 的工作台密度和局部图探索方式，不照搬其品牌、图标或所有文件操作。

- 复用现有主题变量，并建立 Surface/Border/Text/Muted/Accent/Selection 对应关系；图、分析、侧栏、证据使用同一套 tokens。
- 浅色用低饱和中性背景、白色阅读面板；深色使用有层次的近黑灰，不全站纯黑。主题以用户选择为准。
- 建议强调色沿用产品现有主色；禁止每个组件临时选蓝/青/紫，导图浅色页里也不能固定深底浅字。
- 内容字号正文 14–16px、正文行高 1.6–1.8；辅助信息 12–13px；标题有层级但不占满首屏。间距采用 4/8/12/16/24，面板圆角 8–12px，边框轻、阴影少。
- 图谱节点以小圆点/圆形为主，文字按缩放与交互渐显；选中节点、邻居、非相关节点有清晰层次。语义靠图例和形状/文字共同表达，不只靠颜色。
- 普通流程不显示 quote_hash、parser version、token budget、数据库字段名；放入可折叠技术详情/开发诊断。
- 全站功能名称统一用“文档分析 / 分析笔记 / 总结 / 思维导图 / 知识图谱 / 查看原文”；“洞察”可作内部名，不要求用户猜含义。

### 7.2 可用性、响应式与访问性

- 1440×900、1280×800：主工作区可用，标题/工具栏不遮画布；除导图画布拖动外不出现整页横向溢出。
- 768px：原文/分析改为单主面板切换，图谱详情可抽屉；390×844：核心操作、节点详情和结果阅读可完成，触控目标建议至少 44px。
- 工具按钮有 label/tooltip，异步操作禁用与加载态一致；抽屉/弹窗支持 Esc、焦点进入与返回；键盘可访问列表作为网络图替代。
- 加载、空数据、无关系、无匹配、失败、过期、权限失效分别设计，不能全用一个“暂无数据”。
- 遵循 reduced-motion；力导向布局可暂停；内容对比与焦点态能在浅深主题辨认。

### 7.3 设计交付必须先有可检查样张

首个实施批次先交三张带真实示例内容的高保真页面：分析工作台（含原文定位）、思维导图、笔记全局/局部图（可同页状态组合）。样张可以用静态前端数据渲染，但需标注为样张，后续必须连接真实接口。

不要求每个按钮都等用户批准才开发；开发者需按本任务书自行完成样张检查、真实布局和回归。有新增重大产品取舍才询问。若用户审阅后调整方向，沿同一设计契约修改，不另造页面风格。

## 10. 必测数据、失败分支与性能目标

### 10.1 固定验收样本

准备隔离测试数据：12 篇笔记，包含 A→B、B→C、A→C、双向引用、重复引用、同名两篇、孤立笔记、未解析链接、手动关联和第二用户的不可读笔记。另有小型 PDF、Markdown、TXT、DOCX、PPTX 与一份超预算长文，内容可公开且无需个人数据。

### 10.2 功能矩阵

| ID | 必测场景 | 通过标准 |
|---|---|---|
| ENTRY-01 | 不知道隐藏 URL 的用户从首页导航进入分析/图谱 | 桌面与手机均有可见入口，最多两次明确点击，不靠提示词或地址栏 |

| ANALYSIS-02 | 点关键结论的第 2 条来源 | 原文准确定位，高亮当前来源，支持返回，非只显示引文 hash |
| ANALYSIS-03 | 新笔记/保存失败/编辑后分析 | 成功保存才分析目标版本，失败不离页不丢草稿 |
| ANALYSIS-04 | 刷新、A/B 路由快切、账号退出、失败重试 | 从服务端恢复任务，旧响应不污染新资源；不重复计费/重复 job |
| ANALYSIS-05 | LLM 生成期间删除/修改来源、缺证据、恶意输出 | 不发布旧版本/虚假来源；明确过期或不足；提示注入不扩大工具权限 |

### 10.3 性能与测量

验收规模：导图 100 节点；笔记图 300 节点/1000 边可操作；隔离数据 1000 篇笔记时按需加载，不能一次请求全部正文。超限显示当前范围/更多数据提示；不伪称可见子图就是完整库。

项目目标：在记录型号/浏览器/构建方式的普通开发电脑、生产构建、数据已返回条件下，300/1000 图首次可操作不超过 3 秒；拖动/缩放不持续阻塞交互，目标接近 30fps 或更好；导图折叠/搜索目标 200ms 内响应。以上是待测目标，不是当前测量结果；记录 p50/p95 或可复现性能轨迹，未达标需优化或明确缩小默认加载上限。

不要求本地/远程 LLM 在固定几秒完成；记录模型、长度、预算和时延，任务状态及时反馈。SQL 查询次数随批量页数增长，不能每个可见节点单独查一次完整笔记。

## 11. 验收与交付证据

### 11.1 分层验证

- 后端：链接解析、版本/锚点、导图 schema、权限、幂等和失效单测；API 契约和真实数据库迁移验证；模型使用固定返回覆盖错误分支，另独立做真实模型质量抽样。
- 前端：组件交互、路由切换迟到结果、保存失败、任务恢复、图谱与导图状态单测；lint/build 继续执行。
- 浏览器：Playwright 从主导航进入，不只直接 goto 深层路由；真实登录和授权接口完成两来源分析与笔记网络流程。允许另有 mock 场景测边界，但不能把 mock 成功当真实全栈成功。
- 质量：展示的来源不得伪造；引文存在与结论正确分别评估。沿用原任务书真实来源定位与人工抽样目标，记录分母、失败样例和降级格式；没有运行真实模型就写“模型质量未验证”。
- 回归：原笔记 CRUD、上传/索引、问答引用、相关笔记和用户隔离可用。测试环境必须隔离，不把业务数据库和付费模型默认当测试依赖。

### 11.2 必交产物

1. 需求 ID → 生产入口 → 自动化用例 → 真实页面证据的验收矩阵，逐条通过/未通过；不能用测试总数增长代替产品验收。
2. 三个主页面在 1440×900 的浅深截图；390×844 的关键流程截图；图谱 1/2 跳与选中状态、分析来源高亮、导图折叠编辑状态。
3. 连续录屏：从导航选择一篇文档→分析→导图→点击原文；再打开笔记 A→插入 B 链接→全局图→局部图→打开 B→查看反链。录屏可分两条，但必须来自最终实现。
4. API/迁移与数据回退说明；依赖选型；旧概念图保留与路由兼容说明；模型与异步 worker 配置说明。
5. 最终代码 SHA 或 dirty diff 摘要、实际执行命令、测试/性能结果。不能引用旧迭代文档的 1140/71 数字冒充本轮通过。

以下情况一律不通过：导航找不到功能；只展示圆形节点/静态 SVG 或缩进树；图谱必须先分析才有数据；标签/相似度冒充正文链接；节点不能打开笔记；来源不能定位或虚构页码；布局只在一张静态截图好看；演示数据与真实接口切换后功能失效。

## 12. 最终演示脚本与范围确认

### 场景 A：分析内容

用户进入“文档分析”，从知识库选择文本型 PDF《检索增强生成》→生成并看到真实任务阶段→阅读章节总结→切思维导图、折叠分支→点击其中一个要点的来源→原文定位到实际页/片段→把选定结果保存为新笔记并保留来源。随后用一篇已有笔记重复分析流程，证明不是 PDF 专用功能。

### 场景 B：组织笔记

用户创建“RAG”“向量检索”“评测”三篇笔记，在 RAG 正文通过 `[[` 选择向量检索，在向量检索正文链接评测→无需调用 AI 即可在知识图谱看到三篇笔记和两条真实连线→聚焦 RAG，1 跳见向量检索、2 跳见评测→打开向量检索查看入链段落→改标题、返回图谱仍连接正确→删除某处正文链接，图和反链同步更新。

### 本轮不以这些内容替代完成

跨文档 AI 概念图、自动推荐、更多颜色/动画、算法参数面板均可保留或后续增强；核心路径和真实验收未通过前，不增加这些工作掩盖入口、阅读和笔记链接的缺口。

交接结论：**可按本文直接开展产品改造。** 开发首先核对 P0 页面与接口契约，在同一工作区保留已有实现并按 P0—P5 完成。本文没有要求先重做历史整改、引入图数据库或全面更换技术栈。
