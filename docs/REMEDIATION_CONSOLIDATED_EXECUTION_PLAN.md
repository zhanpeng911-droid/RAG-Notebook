## 2. 当前事实与不变量

### 2.1 源码核对结论

| 当前实现 | 已有进展 | 本轮必须继续覆盖 |

这些是源码事实/设计风险，不冒充已经运行的失败实验。A 批应先取得对应有效行为证据，避免重复修复已经正确的路径。

### 2.2 所有批次共同遵守

1. 资源身份为 owner + document_id，执行身份再包含 generation + 完整 token/执行 ID。MD5 是指纹，不是授权身份。
2. 只有当前执行可条件发布；发布指针、执行关闭和 superseded 清理任务同 SQL 事务持久化。已发布事实确认继续接受清理任务 `done`。
3. 删除任务登记与删除同事务；清理精确到本资源及目标代次。先证明对应写入者关闭，再最终清理查空；unknown 不能因超时自动当 closed。
4. 已失去身份的旧请求不得覆盖删除、新代次或新文件。状态相同不意味着仍是同一轮执行。
5. SQL/Chroma 无跨库事务；取消 await 不等于线程停止，查询失败不等于不存在，commit 抛错不等于回滚。
6. 拒绝正文不得进入 reranker、模型、推荐或缓存返回；管理状态查询仍可展示本人失败/待处理记录。
7. 歧义存量不猜归属、不盲删、不静默丢弃；测试不能用 skip/xfail、吞取消、放宽断言换通过。

## 5. A：一次完成恢复与接管，不再按单缺陷反复返修

### A1. 结构化恢复身份与审计

采用现有执行记录作为恢复事实的载体。拟增加 `recovery_outcome`、`recovered_at` 等最小字段，取值明确区分可重试与需重传；字段命名遵循现有风格。完整执行身份已有字段，不再用 `execution_token[:24]` 或 `error_message` 子串作为恢复凭据。错误文案仅展示给人。仅在必要时新增迁移，不修改已应用迁移文件；不为历史记录伪造恢复成功。

恢复状态变更、结构化恢复结果和成功审计使用同一会话、同一事务；resolve 的关闭变更与成功审计也同事务。复用现有 AuditLog，传入 operator/reason/evidence 与精确 resource_id，禁止路由在服务已经 commit 后才补写唯一审计依据。dry-run 可追加访问审计，但不得改执行、文档或恢复凭据。

恢复是一次性动作，重放是事实读取：同身份重放不重复改状态、分配代次或产生第二次“实际恢复”记录；可追加重放访问审计。文档已删除/推进时返回当前 gone/conflict，不将历史恢复记录包装为当前可接管资格。完整身份不匹配必须拒绝。

提交抛错：先释放原事务，再独立读取恢复事实与当前文档身份。确认已提交则重建结果；确认读取失败则返回 `uncertain` 并保留依据，不记录“确定未持久化”。若审计写入失败，应与本次状态变更一起回滚；若确认响应丢失，重放不得重复执行。

### A2. 接管资格、ABA 与文件一致性

同名、同 MD5 入口只做资源定位，统一走一个接管编排，不各复制一份资格逻辑。

1. 将观察到的 generation、旧文件身份、owner/document_id、恢复资格作为预期值传入仓库。条件更新不仅检查 index_failed，还检查这些预期值，防住 failed→pending→indexing→failed 后旧请求再次命中的 ABA。
2. 使用结构化 `needs_reupload` 恢复事实授权接管，并确认相关旧写入者已经关闭。普通失败但仍有 unknown/writing 的文档不得因磁盘文件不存在而被接管。历史缺文件失败先走受控恢复/核验，不由上传接口自动推断停止。
3. 复用统一文档锁/条件领取协议。读取 open executions 与状态修改必须在一致锁顺序下复核；单独做一次 NOT EXISTS 查询不是并发证明。检查所有会登记新 execution 的路径是否参与同一协议。
4. 文件先进入本次请求独有的受控路径，校验类型、大小、内容后才提交身份；更新文件身份、消耗恢复资格与 pending 状态同事务。文件系统不与 SQL 原子，必须处理 SQL 提交结果不明：确认引用归属前不删除可能已经生效的文件。
5. 条件未命中不索引、不修改胜者文件；仅处理本请求确知未被引用的临时文件。不要用异常分支宽泛删除共享目录。
6. 同文件名不同内容、同内容不同文件名复用原 document_id 时，保持当前文件名唯一约束、owner/space 归属及明确的显示名契约；不能借接管改变所属空间或绕过其它文档的去重/授权。
7. 接管提交后复用既有同步/后台调度策略，不默认强制所有上传同步执行；入队失败保留可补偿 pending 依据，不误报已完成。只允许一个新代次领取者。

### A3. 生命周期与 HTTP 结果完整接线

- 区分 `published`、普通可重试失败、`recovery_required/uncertain`、等待、冲突、需重传；内部结果可扩展结构化分类，但同步更新 v1/v2/SSE/Celery/Beat/前端调用方，不能留下 `retryable=True` 与数据库 indexing 矛盾。
- 已确定冲突/仍有写入者用 409；不能确认提交或依赖不可用用 503 类明确暂时失败；401/403 保持现有鉴权契约。SSE 无法改已发 HTTP 状态时发送相应错误终态，发布前不发送 completed。
- unknown 的 `closed_at` 必须为空；确定关闭才记录停止时间。租约过期只观测失联；活动线程未结束时不能由测试或运维说明伪造停止证明。
- 列出所有写入口的领取前、领取提交、解析、向量写入、发布提交、响应终态分支。领取提交结果不明时不得未确认就开始写向量；取消继续传播；主记录不存在也能收尾自身执行。
- resolve 请求应精确绑定执行身份，默认 dry-run，权限与理由校验不因测试变更而放宽。运维规程明确先停写/排空并核验真实请求结束；unknown 状态本身不是停止证据，不宣称接口能验证自由文本的真实性。
- 清理等待 writer 不计失败预算；检查立即到期反复领取是否造成饥饿，采用有界、公平调度。清理续租、过期持有者回写、blocked 人工可见性按旧 K3/N2 余项核对，不漏项。

## 6. B：统一新协议读取和接口契约

### B1. 实施设计

拟新增 `backend/app/services/document_visibility_service.py`，复用现有权限服务，新增按 document_id 的批量 SQL 查询。公共结果区分允许、拒绝和依赖失败；失败默认不返回正文，不能退回原始向量。

先查当前授权资源/active_generation，再取对应向量，最后在内容离开服务边界前复核。向量 metadata owner/document/generation 均要匹配；MD5 字典不能替代文档身份。批量查询有明确上限，不能每块一条 SQL 或拉全库正文再过滤。

新协议严格过滤与 C 的 legacy resolver 接口同时定义：只有经验证映射才能解释缺 document_id/generation 的旧数据。B 可先在专用新协议数据验收，不向业务范围提前切换、不设置可绕过授权的生产开关。

### B2. 全入口矩阵

| 入口 | 接线与边界 |
|---|---|
| 知识内容列表 | SQL 可读资源一文档一项，再批量取摘要；统计与分页同范围 |
| 管理状态列表、Agent 资源发现 | 管理用途保留本人 pending/failed/待核验提示；作为检索候选时按正文规则 |
| 文件名详情 | 按现有 owner/space 契约定位唯一 document_id；歧义冲突，不取第一个 MD5 |
| 分块列表、chunk ID 直读 | active 代次、稳定块排序；缺块不回退旧代次，缺归属拒绝 |
| RAG/Agent/关键词兜底 | 在 rerank/模型前过滤；有限补召回不能绕过授权 |
| 相关知识与笔记 | 知识走公共可见性，笔记走自身权限与删除规则，保留资源类型 |
| 单图、批量图、MD5 记录、debug metadata | 资源解析与权限同规则；路径存在不表示资源可读，原路径穿越防护保留 |
| 缓存 | 查实际缓存后确定范围；命中也须最终授权，删除/撤权/代次变化不能返回旧正文 |

当前知识 list 没有分页参数；不得偷偷截断前 100 条。D 中成组交付分页请求/响应/前端契约，或保持已明确的旧接口契约并说明可扩展方案。不得静默改变同名唯一范围为“空间级”。

### B3. 验收

每个实际入口至少参数化覆盖：本人/他人、跨空间、同 MD5 A/B、active/旧代次、deleting/index_failed、缺 metadata、SQL 故障。增加“返回前撤权/删除”交错，断言禁用正文从未进入模型上下文。跨库不是原子快照：已发送字节不能撤回，但删除提交后的新请求必须拒绝。

检查 SQL 查询次数随批次数而非 chunk 数增长；记录真实计数和页上限，不编造性能指标。没有结果缓存的路径标“不适用”，不为验收新增缓存。

B 退出：新协议入口矩阵通过、API 兼容约定与 legacy resolver 输入输出冻结，进入 C。

## 7. C：存量映射、盘点和可恢复工具

### C1. 持久映射

拟新增专用 legacy mapping 模型/仓库和迁移。最小字段：数据源/collection 身份、旧向量 ID、owner、document_id、兼容 generation、有效状态、来源批次、证据摘要。唯一键包含数据源身份；generation=0 只代表已核验旧版本，不是缺字段通配符。

优先只登记 SQL 映射，保持旧向量 ID 不变，避免无必要的跨库复制。文档发布新代次后旧映射不能继续作为 active 正文返回。映射来源必须有可核验关联；同用户同 MD5 只找到一条 SQL 文档也不自动证明归属。

### C2. 工具接口（拟新增）

在现有工具目录风格下实现 inventory、dry-run、apply、status、resume、rollback。默认只读，apply 显式提供审核 manifest 摘要、精确数据源/collection、owner/space 范围和批次 ID。空范围拒绝，不默认全库。

- inventory 分页分类：旧随机 ID、固定 ID、MD5 代次 ID、document_id 代次 ID、损坏 metadata、附属图片。输出唯一可映射、冲突、无归属和损坏项，报告不含正文/密钥。
- dry-run 产出数量对账、证据摘要和拟改动，零 SQL/Chroma 数据源写入。写本地报告与修改数据源必须区分。
- apply 复核源版本/metadata 摘要和当前 SQL 身份；源已变化则冲突，不覆盖。每项/页持久化进度，以稳定扫描/冻结范围避免 offset 变化漏项。
- resume 与重复 apply 不重复创建记录；失败项可重试但不能扩大目标范围。rollback 仅撤销本批且尚未被后续操作改变的映射，不改原向量或新业务状态。
- blocked 清理任务通过已核验映射逐项重评估；保留原因和审计，不批量解锁，更不能恢复 MD5 宽泛删除。
- 执行租约/旧写入者和目标完整性仍须证明；映射成功不是“所有写入者已经关闭”的证据。

### C3. 验收

专用样本覆盖 dry-run 零写、相同 ID 不同 collection、同 MD5 多资源、无来源证据、源变化、旧块数大于当前 chunk_count、页中断/进程退出、重复 apply/resume、受限 rollback。映射后通过 B 的真实服务读取，不能只断言映射表多了一行。所有冲突原数据保持不变。

C 退出：工具在隔离样本运行并产物完整，legacy resolver 接入 B；真实业务盘点/apply 仍等待明确范围授权，不伪称业务迁移完成。

## 8. D：联合路径、前端与兼容切换

完成列表/详情/分块/检索/推荐/图片/缓存全部接线，给每个入口在台账中填写实际调用方与测试。不能只给公共 helper 写测试。

前端保持原产品行为，必要最小修改：管理页明确展示待核验、需重传和失败；不把 503 当空列表，不把 pending 当 indexed；重传能使用后端真实恢复结果；新增分页时同步更新 API、页码/游标、total 和空页处理。不以 UI 重构扩大范围。

联合矩阵：新上传、合法旧映射、未解析旧数据、同 MD5 A/B、跨空间资源，分别执行上传/读取→重索引→代次切换→删除→再次读取；覆盖前端退出登录/切换用户后迟到响应，以及成员撤权与缓存命中。图片若不能证明归属，明确拒绝并登记兼容影响，不放宽目录权限。

切换准备输出：映射覆盖对账、未解析清单、影响范围、回退方法。未解析数据不能静默消失；真实切换需要数据所有者接受该范围的不可用项或先完成处置。回退不能恢复宽泛授权或重新暴露已删除内容。

D 退出：B/C 全矩阵与前端 unit/lint/build、适用浏览器测试通过，形成可用于 E 的确定性种子和用户操作脚本。

## 9. E：隔离真实集成，不等待推送才能做

### E1. 环境

拟新增 `docker-compose.integration.yml` 及专用测试配置。独立 project、宿主端口、卷、数据库、Redis namespace、Chroma collection/目录、账号和确定性 provider；不加载业务 `.env`，不挂载业务目录。启动前解析最终 Compose config 并验证目标隔离；不能只加 `-p` 而保留冲突的固定 container_name。

Chroma 沿用现有实际持久化模式和锁定版本，不未经设计新增 HTTP 服务依赖。测试 provider 仅在专用配置生效；确定性 provider 证明功能而非真实模型质量。缺配置/服务启动失败是失败，不 skip。

CI 当前 fullstack 启动清单未含 celery-beat；需要分别证明 worker 执行和 Beat 调度接线，不能直接调用任务函数后称调度器已验收。

### E2. 场景与证据

| ID | 场景 | 验证重点 |
|---|---|---|
| E-01 | 空库→最终迁移 head，代表性旧样本→head | 实际 MySQL 版本、升级数据保留、危险 downgrade 拒绝；不在业务库执行 |
| E-02 | 两个独立 MySQL 连接，A 的恢复/删除/接管/发布/ABA 屏障 | 连接身份不同、原事务已释放、另一方提交确实可见、条件写唯一胜者；有界锁超时 |
| E-03 | 真实 Chroma add/get/delete，写入取消后迟到落库 | unknown 阻止 done；真实结束后精确清理收敛；同 MD5 A=g2/B=g1 不互伤 |
| E-04 | 子进程领取后、写完后、发布边界退出并重启 | 持久依据可发现，租约失联不假关闭；恢复后无孤儿执行/错误清理 |
| E-05 | 真实向量存量样本盘点→apply→读取→resume/rollback | 映射读取、冲突保护、数量对账，不能用假向量库代替 |
| E-06 | 统一网关 HTTP/浏览器全链路 | v1 单/多/SSE、v2/worker、读取/推荐/图片/删除/撤权；不止登录与笔记 CRUD |
| E-07 | worker/Beat 启停、队列故障、租约和公平调度 | 状态提交后才调度；任务遗留可补偿；等待不阻塞其它清理 |

MySQL 需报告实际版本；若支持现有 8.0.12 部署，至少在该目标或明确兼容环境补证明，不以 SQLite 代替。锁等待实验给出连接 ID/事务窗口的脱敏证据，不能把两个包装对象称作双连接。

区分“commit 后抛 Python 异常”的组件注入与“真实数据库连接中断”的集成实验。后者只在专用库/进程实施，失败保护不得影响宿主业务连接。

每场景保存 run ID、代码 SHA/dirty diff 摘要、服务版本、种子摘要、执行命令、断言、脱敏日志。失败保留证据，清理仅针对本次创建且已核对标识的资源；不写宽泛 `down -v` 或递归删除脚本指向未知目标。

E 退出：本地真实集成通过。远程 CI 需对应授权后的最终 SHA；未授权推送时完成 CI 配置和本地产物，单独登记远程证据未取得。

## 10. F：最终门禁、报告与总验收

### F1. 测试节奏与命令

每批先定向行为测试和受影响模块测试，修复所有新增失败。避免每改几行跑两次全量；A 完成做一次后端完整门禁，B/C 按影响扩展，D 做前后端联合门禁，最终同一代码快照独立进程跑两次后端全量（一次带覆盖率）。新增失败先诊断，不能靠第三次绿掩盖偶发。

先确认测试 fixture 与连接配置，再在 `backend` 现有虚拟环境运行；不是直接复制命令就安全。单元环境强制假凭据、不可达 MySQL/Redis/provider，`REDIS_CACHE_URL` 与 `JWT_BLACKLIST_REDIS_URL` 用 Python `os.environ` 显式空字符串覆盖，防止 PowerShell 空值移除后由 `.env` 回填。真实集成另用 E 的专用配置。

```text
python -m pytest <本批测试路径> -q --runxfail --no-cov -p no:cacheprovider
python -m pytest tests --ignore=tests/functional -q --runxfail -p no:cacheprovider --cov=app --cov-report=term --cov-fail-under=85
python -m pytest tests --ignore=tests/functional -q --runxfail --no-cov -p no:cacheprovider
python -m pytest tests/functional -m "not real_api" -q --no-cov -p no:cacheprovider
python -m ruff check app tests
python -m mypy app/core app/schemas app/utils app/config
```

`front`：`npm run test:unit`、`npm run lint`、`npm run build`，使用 E 环境跑 `npm run test:e2e:full`。Django 复用 CI 对应测试命令并使用隔离数据库；最终部署门禁不漏 Django。安全扫描继续按既有 CI 政策，不为了通过扩大漏洞豁免。

真实集成与付费 real_api 分开统计；deselected/skip 不算通过。新增测试文件需复核收集列表，防装饰器丢失或测试区被拼接截断。禁止源码字符串断言代替生命周期行为。

### F2. 交付文件

1. `REMEDIATION_ACCEPTANCE_MATRIX.md`：旧编号→A—F→真实 node ID/产物；全部状态为通过、失败、未验证或不适用，不用含糊的“基本完成”。
2. DELIVERY 追加统一实施段：基线、实际改动、红证据、门禁、集成结果、未授权外部操作；更正旧 N1 完成口径但不抹去历史记录。
3. 运维说明：unknown 核验前提、resolve/reconcile dry-run/apply、重放/503 处置、需重传、blocked 排查、存量盘点/apply/resume/rollback、隔离环境清理。
4. 接口变化说明：新增结果分类、HTTP/SSE 语义、前端分页与兼容影响；迁移 upgrade/downgrade 风险和恢复操作边界。
5. 最终脱敏证据索引；有 Git 授权时按完整逻辑切片提交，无授权则保留明确 diff。远程 CI 必须绑定实际最终 SHA，不用早期 SHA 或旧截图替代。

### F3. 总验收条件

- A：未知执行、恢复、重传、审计和提交确认安全闭环；所有组件窗口真实命中。
- B/D：所有实际读取入口统一身份与权限；管理状态可用；缓存、图片、推荐、前端无旁路。
- C/D：存量样本兼容可用、工具默认安全、重复/中断/回退可恢复；歧义与业务切换范围明确。
- E：真实 MySQL/Chroma/进程/Compose 场景完成，测试层级不混写。
- F：最终快照门禁与台账完整；历史余项无遗漏，已授权范围内无待实现工作。

结果分层表述：可以分别说“代码与组件验收通过”“本地真实集成通过”“当前 SHA CI 通过”“业务切换完成”。缺 CI 或业务授权不能伪称整体验收/生产上线完成，也不能借此停止已经授权的本地实现。

## 11. 断点与异常处理

上下文不足时保存台账：完成到哪个测试、当前失败实际输出、改动文件、下一条具体命令；恢复后继续，不重写方案、不丢红证据、不反复从旧基线开始。不要以“上下文将尽”把失败标 xfail 后称本批完成。

只有确实缺授权/外部条件/影响产品语义的选择才请求用户决策；报告具体阻塞并继续可独立完成的工作。发现同范围缺陷加入对应 A—F 行并修到验收，不再单独交付“一轮修四条、下一轮再补两条”的碎片方案。
